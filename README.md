## About

<img align="right" alt="LUC4N3X workspace" width="360" src="./assets/brand/luc4n3x-about.webp" />

I'm LUC4N3X, an independent developer based in Italy. Most of my work goes into Android apps, desktop audio software, and the Linux backend services behind them.

My main project is [Levyra](https://github.com/LUC4N3X/Levyra-deepsound), an open-source music player I maintain across Android, Windows and Linux. Outside of Levyra, I build media extraction pipelines, self-hosted tools, and workflow utilities like [antigravity-thalarch](https://github.com/LUC4N3X/antigravity-thalarch).

I prefer software that holds up on mid-range phones and keeps user data local.

Levyra is an open-source music player built for listening without an account. It runs on Android, Windows and Linux, combining streamed tracks and local audio files in one library. Android playback runs on AndroidX Media3 and ExoPlayer, desktop builds use Compose Multiplatform with libVLC, downloads are saved as ordinary audio files on your storage, and synced lyrics come from LRCLIB. It has no ads and no telemetry.

## Stack

<img align="right" alt="Linux development workstation" width="360" src="./assets/brand/luc4n3x-linux-stack.webp" />

My daily workstation runs Linux. I stick to dependable tools that behave predictably under load.

- **Client apps.** Kotlin, Jetpack Compose, Compose Multiplatform, AndroidX Media3, ExoPlayer and libVLC.
- **Backend and extraction.** Python with FastAPI and AsyncIO, plus Node.js and TypeScript for web services and tooling.
- **Storage and delivery.** SQLite and Room for offline-first local state, Redis for caching, Docker containers behind Cloudflare, and GitHub Actions for CI and releases.

## Engineering habits

Most of my projects start from a concrete annoyance I run into myself. Once the first version works, the real time goes into making it hold up in daily use.

- **Test on real hardware.** Background limits, audio focus and battery managers behave very differently on a mid-range Android phone than on an emulator, so playback changes get verified on physical devices.
- **Fix the root cause.** When a bug comes back, the first fix only masked it. I'd rather spend an evening reproducing a race condition than ship a retry wrapper around it.
- **Keep commits small and readable.** Each change targets one problem so `git blame` and release diffs stay useful six months later.
